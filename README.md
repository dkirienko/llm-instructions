# llm-instructions

Одностраничный сайт на GitHub Pages, содержимое которого предназначено для чтения
языковой моделью или агентом в автоматическом режиме.

## Что отдаётся наружу

| Адрес | Формат | Для чего |
|-------|--------|----------|
| `/` | HTML | просмотр человеком, чтение браузерным агентом |
| `/llms.txt` | `text/plain` | **основная точка для LLM**: полный текст без разметки |
| `/raw.md` | Markdown | тот же текст для агентов, ждущих Markdown |
| `/robots.txt` | — | явный разрешсконкретным краулерам (GPTBot, ClaudeBot, PerplexityBot, …) |

## Как отредактировать

Правьте **два файла**, остальное генерируется:

1. `content.md` — сам текст инструкций. Обычный Markdown, поддерживаются таблицы
   GFM и блоки кода с тройными обратными кавычками.
   Заголовок первого уровня `#` писать не нужно: он берётся из `site.json`
   и вставляется автоматически.
   HTML-комментарии `<!-- -->` в начале файла считаются служебными и в выдачу не попадают.
2. `site.json` — метаданные: заголовок, краткое описание, версия, аудитория, адрес.

Затем пересоберите и закоммитьте:

```bash
python3 tools/build.py
git add -A && git commit -m "Обновил инструкции"
git push
```

Зависимость сборки — `python-markdown`:

```bash
pip install markdown
```

## Состав репозитория

```
content.md            ← текст инструкций (правите вы)
site.json             ← метаданные (правите вы)
templates/index.html  ← вёрстка страницы (правите только если нужен свой дизайн)
tools/build.py        ← генератор: content.md + site.json → index.html, raw.md, llms.txt
index.html            ← результат сборки, коммитится в репозиторий
raw.md                ← результат сборки
llms.txt              ← результат сборки
.nojekyll             ← чтобы Pages не прогонял Jekyll и не ломал .md
```

Собранные файлы коммитятся: GitHub Pages раздаёт их как есть, без сборки на стороне
GitHub, поэтому сайт работает сразу после push.

## Проверка перед коммитом

```bash
python3 tools/build.py --check
```

Код возврата `0` — закоммиченные файлы соответствуют исходникам, `1` — забыли
пересобрать. Этот же вызов можно повесить в CI.

## Включение GitHub Pages

Первый раз, после `git push`:

```bash
gh repo create dkirienko/llm-instructions --public --source=. --push \
  --description "Инструкции для чтения LLM в автоматическом режиме"

gh api -X POST repos/dkirienko/llm-instructions/pages \
  -f source[branch]=main -f source[path]=/ \
  -f build_type=legacy
```

Дальше сайт живёт по адресу
`https://dkirienko.github.io/llm-instructions/`.

Если в репозитории нужен свой домен, добавьте в `site.json` поле `"domain"`
и пересоберите — `build.py` подставит его в канонический адрес.

## Что делает страницу удобной для машинного чтения

- Ноль JavaScript: весь текст в исходном HTML, агент получает его первым запросом.
- Семантическая разметка: разделы — `h2`/`h3`, команды — `pre`/`code`, параметры — таблицы.
- Дублирование контента в чистом виде, чтобы не разбирать HTML.
- Версия и дата в метаданных, чтобы агент мог отсеять устаревшую версию.
- `link rel="canonical"` и `link rel="alternate"` на машинные версии.
- Указан `lang`, кодировка и `viewport`.
